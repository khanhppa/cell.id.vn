Base URL: — — không bật CORS, API dành cho gọi server-to-server. Tài liệu đầy đủ nằm ở /API.md trong mã nguồn.
Khoá API là cổng kết nối, không gắn tài khoản. Mỗi ứng dụng ngoài giữ 1 khoá để chứng minh được cấp phép và chịu hạn mức. Muốn tra cứu, ứng dụng phải cho người dùng đăng nhập (lấy JWT) rồi gửi kèm khoá — điểm sẽ trừ vào tài khoản đăng nhập.

1. Xác thực

Tra cứu cần cả hai header: khoá (cổng) + JWT (tài khoản bị trừ điểm).

X-API-Key: sk_live_xxxxxxxxxxxxxxxx
Authorization: Bearer eyJhbGciOi...   # JWT từ /api/v1/login

Chỉ gửi khoá mà không có JWT → 401 USER_REQUIRED. Endpoint công khai (/health) không cần header nào.

2. Kiểm tra kết nối (không cần xác thực)

GET /api/v1/health

3. Đăng nhập — trả JWT + thông tin tài khoản

POST /api/v1/login
Content-Type: application/json

{ "username": "user01", "password": "matkhau" }

→ 200 { "ok": true, "apiVersion": "v1", "token": "eyJ...",
        "expires_in": 86400,
        "user": { "id": 12, "username": "user01", "email": "...",
                  "role": "user", "status": "active",
                  "credit_balance": 95 } }

4. Thông tin tài khoản đang đăng nhập

GET /api/v1/me
→ 200 { "ok": true, "user": { ...số dư, email, vai trò... },
        "auth_type": "key+jwt",
        "key": { "id": 3, "name": "My app", "scopes": ["lookup","account"],
                 "rate_limit_per_min": 60, "require_user": true } }

5. Tra cứu cell

Query: mcc, mnc, lac, cellid (bắt buộc); sector, radio (tuỳ chọn).

GET /api/v1/cells/resolve?mcc=452&mnc=01&lac=9000&cellid=123456

→ 200 { "ok": true, "found": true, "source": "local",
        "radio_source": "declared", "radio_confident": true,
        "credit": { "balance": 94, "charged": 1 },
        "cell": { "mcc": "452", "mnc": "01", "lac": "9000",
                  "cellid": "123456", "sector": "1",
                  "lat": 21.0278, "lon": 105.8342,
                  "range": 500, "radio": "LTE",
                  "address": "..." } }

→ 404 { "ok": false, "found": false, "reason": "CELL_NOT_FOUND" }
→ 402 { "ok": false, "found": false, "reason": "INSUFFICIENT_CREDIT" }
→ 429 { "ok": false, "reason": "RATE_LIMITED", "retryAfter": 42 }

6. Hạn mức

Mỗi response kèm header:

X-RateLimit-Limit: 60
X-RateLimit-Remaining: 58
X-RateLimit-Limit-Day: 5000
X-RateLimit-Remaining-Day: 4912
Retry-After: 42        (chỉ khi 429)

7. Mã lỗi

HTTPreasonÝ nghĩa

401NO_CREDENTIALSKhông gửi header xác thực
401USER_REQUIREDCó khoá nhưng chưa đăng nhập — cần gửi kèm JWT
401INVALID_KEY / INVALID_TOKENKhoá hoặc token sai
401KEY_REVOKED / KEY_EXPIREDKhoá bị thu hồi hoặc hết hạn
402INSUFFICIENT_CREDITTài khoản không đủ điểm
403KEY_DISABLED / ACCOUNT_DISABLEDKhoá bị tắt / tài khoản bị khoá
403INSUFFICIENT_SCOPEKhoá thiếu quyền lookup/account
404CELL_NOT_FOUNDKhông nguồn nào có cell này

Cấu hình hệ thống

Giới hạn số lượt tra nguồn online cho mỗi lần xử lý batch. Đặt 0 để tắt tra online. Đặt bất kỳ số nào (không trần).
Nguồn Google Geolocation trả 1 toạ độ cho CẢ NHÓM cell, nên chỉ gom tối đa bấy nhiêu cell miss vào 1 request — nhóm càng lớn càng dễ trộn cell của nhiều vị trí khác nhau. Google tính phí theo request, đặt nhỏ để tiết kiệm.
Lịch sử tra cứu cũ hơn số ngày này sẽ tự động bị xóa (job chạy 03:30 mỗi ngày).
Khi đóng: người dùng thấy trang thông báo bảo trì ở trang chủ và mọi API nghiệp vụ bị chặn. Chỉ admin đăng nhập được và có thể bật lại.
Hiển thị ở trang /maintenance.html. Để trống = thông báo mặc định. Nội dung là văn bản thuần (không dùng HTML).
Số điểm trừ cho mỗi lượt tra cứu.
Số điểm tặng cho user mới khi tạo tài khoản. Đây là nguồn điểm duy nhất lúc tạo — muốn thêm thì dùng nút "Nạp điểm".
Admin cần tạo kênh thanh toán trên my.payos.vn để lấy Client ID / API Key / Checksum Key. Số tiền nạp sẽ được quy đổi ra điểm theo tỉ lệ bên dưới.
Bật chế độ test để thử luồng nạp hoàn toàn offline: link thanh toán trả về nội bộ, admin dùng nút Giả lập đã trả tiền ở trang Nạp điểm để cộng điểm.
Chỉ điền khi payOS cung cấp môi trường sandbox riêng.
Dùng để tạo returnUrl/cancelUrl. Production nên điền để link trả về đúng tên miền HTTPS.
Ví dụ 1000 → nạp 50.000đ được 50 điểm.
Áp dụng cho cả nạp tự do lẫn các gói nạp bên dưới.
Bật để gắn thẻ GA4 vào các trang public qua /ga.js. Điền thêm Property ID + Service Account JSON để xem số liệu truy cập ngay trong Dashboard.
GA4 → Admin → Data streams → Web stream → Measurement ID.
GA4 → Admin → Property settings → Property ID (KHÔNG phải Measurement ID).
Các bước lấy thông số Google Analytics
  1. Vào Google Cloud Console → tạo project → bật Google Analytics Data API.
  2. Tạo Service Account → Keys → Add key → JSON → tải file về.
  3. Trong GA4 → Admin → Property Access Management → thêm email service account làm Viewer.
  4. GA4 → Admin → Property settings → copy Property ID (dãy số).
  5. GA4 → Admin → Data streams → copy Measurement ID (G-…).
  6. Dán JSON + 2 ID ở trên → Lưu cấu hình → Kiểm tra kết nối.
Thẻ tracking được chèn tự động vào các trang public qua /ga.js. Trang admin không bị tính vào traffic.
Bật gửi email qua SMTP
TẮT: mã kích hoạt ghi ra console server; admin vẫn copy link ở phần Người dùng. BẬT: cần đủ máy chủ + địa chỉ gửi.
Dùng TLS ngay khi kết nối (implicit TLS — thường là cổng 465)
Nhiều dịch vụ không nhận mật khẩu đăng nhập thường — cần "mật khẩu riêng cho ứng dụng":
Gmail / Zoho / Yahoo: App Password (Zoho: App Password)  •  Brevo: SMTP Key  •  Resend: API Key (user = resend)  •  SendGrid: API Key (user = apikey)  •  Mailgun: postmaster@<domain>  •  Amazon SES: SMTP Credential.
Địa chỉ gửi chỉ giữ nguyên khi tên miền đã xác minh (SPF/DKIM) tại nhà cung cấp. Lưu cấu hình trước khi gửi thử.
